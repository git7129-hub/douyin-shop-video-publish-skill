# Agent 操作手册（AGENT-GUIDE）· 抖店短视频自动发布技能

> 本文件是**给执行 Agent 看的机器级操作协议**。你（Agent）接手任务后按此执行。
> 人看配置引导请读 `CONFIG-GUIDE.md`；业务方法论与红线见 `SKILL.md`。
> 一切以**页面真实状态**与**config.json 实际值**为准，禁止猜测。

---

## 0. 启动前（必做）

1. **定位 config.json**：先找技能目录同级的 `config.json`；不存在 → 提示用户「请复制 config.example.json 为 config.json 并完成配置（见 CONFIG-GUIDE.md）」，暂停等待，**不得用示例默认值直接开工**。
2. **读取配置**：解析 JSON，取 `pages.*`、`sheets.*`、`paths.*`、`shops`、`rules.*`。
3. **检查登录**：浏览器打开 `pages.home`，确认抖店已登录（右上角有店铺名）；未登录 → 引导用户企业微信扫码登录（`interaction.request_action` type=browserControl）。
4. **记录时间基准**：取 Windows 本机当前时间，作为发布时间计算的起点。

## 1. 全表扫描（任务读取，禁用固定行区间）

- 打开 `sheets.task_sheet_url`（腾讯文档），等待加载完成（≥5 秒，直至表格渲染出来）。
- 用 JS 读值（在页面 console 或 bu.js 执行）：
  ```js
  const s = window.SpreadsheetApp.workbook.worksheetManager.getSheetList()[0];
  // 逐行读 c0=视频名, c3=店铺, c4=发布时间, c5=备注
  s.getCellDataAtPosition(r, 0)  // A 列，value.r[].hyperlink.url 取视频链接
  s.getCellDataAtPosition(r, 3)  // D 列 店铺
  s.getCellDataAtPosition(r, 4)  // E 列 发布时间（有值=已完成）
  s.getCellDataAtPosition(r, 5)  // F 列 备注（"测试"=测试行跳过）
  ```
- **遍历 0 → 真实末行**（探测到连续空行才算结束；如商品表用 `_Md` 探测真实维度）。
- 判定每条任务：E 有值→已完成跳过；E 空+备注含「测试」→跳过；备注含违规→跳过；否则→待处理。
- 按 D 列分组，输出：`店铺 → [行号: 视频名 | 状态]` 清单。**处理前后各重扫一次**（防遗漏与防重复）。

## 2. 建店队列与并发

- 并发单位=店铺，同时处理 ≤ `rules.max_concurrency` 个店铺；同店严格按行号顺序串行。
- 每店独立状态机：
  ```
  待处理 → 下载中 → 已下载 → 发布中 → 已发布
           ↘ 发布失败（≤3次重试后）  ↘ 人工处理中（暂停本店）
           ↘ 延期（当天窗口外，下一次运行继续）
  ```

## 3. 每店执行循环（核心，逐条串行）

对当前店的每一条待处理任务：

### 3.1 防重复检查
- 重新全表扫描该行：E 列已有值 → 已发布，跳过（绝不重复下载/上传/发布）。
- 状态=已下载 → 检查本地视频文件存在且完整 → 从「3.3 上传」继续；文件缺失 → 重新下载。

### 3.2 店铺校验与切换
- 检查抖店当前店铺 = 任务店铺（右上角店铺名）。
- 不一致 → 首页右上角店铺名区域（约坐标 940,30）→ 店铺信息侧栏 →「切换组织/店铺」→「请选择店铺」弹窗 → 选目标店（列表可能需滚动）→ 验证右上角店铺名已变。
- 无法自动切换 → 暂停本店，引导用户手动切换（提示：请通过右上角个人中心切换到 XX 店铺，完成后点「我已完成」）。

### 3.3 视频下载
- 从任务表 A 列超链接取视频地址（微盘/其他），打开 → 若出现下载按钮 → 点下载 → `bu.wait_for_download(timeout=30)` 拿完整文件（禁止把 `.crdownload` 当完成）。
- 本地已存在同名同任务文件且完整 → 直接复用。
- 页面要求登录 → 引导登录；页面无法识别（非下载页非登录页）→ 暂停人工处理。
- 命名 `店铺名_日期_原名`，AI 作品加 `_AI`（**以来源标注为准，不得猜测**）；移入 `paths.video_dir`。回写状态=已下载。

### 3.4 进入发布面板（挂车判断先行）
- 打开 `pages.publish`，等待加载。
- **读取挂车额度**（页面显示的「今日可发挂车视频 N/M」），以页面实际为准，不询问用户。
- **挂车判断规则**：
  - 当天有挂车额度 → 用**挂车模式**发布，直到额度用完；
  - 当天挂车额度发完 → **不再发布非挂车视频**，本店剩余任务全部延期（状态=延期，记录「已延期，下一次运行继续处理」）；
  - 挂车/非挂车按钮以页面特征判断，无法可靠判断 → 暂停人工处理。
- 点「单独发视频」→ 进入挂车模式面板（挂车额度>0 时）。

### 3.5 上传视频
- `bu.upload_file("input[type=file]", 视频绝对路径)`（隐藏 input，accept=video/*）。
- 等待上传至 100%（出现封面推荐即完成）；页面重渲染失效 input 引用 → 重走面板，勿在旧引用上重试。
- 未确认上传完成**不得进入下一步**。

### 3.6 商品匹配（禁止猜测）
- 商品编号来源优先级：任务备注/用户指定 → 商品ID本地表（`paths.product_id_xlsx`，店铺+型号匹配）→ 商品ID在线表（`sheets.product_sheet_url`，全表扫描，型号→编号）。
- 在面板「选择商品」：
  1. 按「商品名称」label 定位父容器 → 定位其 input → 用原生 setter 填编号 + 派发 input/change 事件；
  2. 点真 `button[type=submit]`「查询」；
  3. 结果唯一 → 勾选第一个 radio → 确认「已选商品（1/1）」→ 确定；
  4. 多个匹配 → **暂停**，列出全部匹配项让用户选（提示：存在多个匹配结果，请选择）；无匹配 → **暂停**，让用户提供编号或按异常流程（提示：未找到该商品编号，请提供正确编号或选「无编号」）。
- 多店铺同型号编号可能不同，以**本店实际查询结果**为准。

### 3.7 标题与作品描述
- 等待平台 AI 自动生成（小黄车标题 + 作品描述）；已生成直接用，未生成 → 自己生成（结合视频/商品/任务信息）。
- 手动编辑描述：点击 `.zone-container.editor-kit-container` → Ctrl+A 全选删除 → `bu.type(ref, 新描述)`。
- 不得留空；生成慢不算失败，继续等待。

### 3.8 违禁词检查（对照 `paths.banned_words_xlsx`）
- 标题与描述逐词比对；无违禁 → 继续。
- 有违禁 → 描述区「已为你生成作品描述」内找 div/span 文本「换一换」（**非 button**）→ 点击。
- 最多自动换 `rules.huan_yihuan_max` 次（默认 5）；**禁止第 6 次**。
- 达上限仍含违禁 → 打开商品ID在线表，**全表扫描**查该型号的「话题栏」→ 找到 → 用其话题替换描述中的违禁话题（按 3.10 方式添加）→ 找不到 → **暂停人工处理**（提示：请手动修改标题或作品描述，或提供合规话题；完成后点「我已完成」）。

### 3.9 AI 内容声明
- 文件名含 `_AI` → 点「无需添加自主声明」→ 选「内容由 AI 生成」。
- 不含 `_AI` → 跳过。

### 3.10 话题添加（SOP 强制，禁止纯文本）
- 输入框输入 `#话题名` → **必须等待下拉选项出现** → 选择**第一个匹配选项** → 确认话题成为标签（DOM 中为 `topicItem` 元素）才计入成功。
- 一条视频随机 3-5 个话题，至少成功 3 个；某话题无法使用 → 不计入，换其他话题。
- 话题来源：商品ID表话题栏 → 用户提供 → 商品相关合规词。
- 挂车流程：AI 生成的描述话题若已是有效 topicItem 标签，核验后无需手动添加。

### 3.11 发布时间计算
- 基准：Windows 本机当前时间；每店独立。
- 当天本店第 1 条 → **立即发布**；第 2 条及后续 → 上一条本店**平台实际发布时间** + `rules.timed_hours_gap` 小时 → **定时发布**。
- 定时输入计算时间后，**以平台显示/调整的时间为准**（早于最早可定时 → 平台自动改到最早可用）。
- 超过当天窗口（`rules.publish_window`）→ 停止本店当天剩余任务（延期），不强行发布。

### 3.12 发布前最终检查（一项不确认就不点发布）
店铺正确 / 仍是目标任务 / 任务表未被他人完成 / 视频上传完 / 商品正确 / 标题与描述存在 / 违禁词已处理 / AI 声明正确 / 话题≥3 / 发布时间正确 / 仍是发布页 / 无阻挡弹窗。

### 3.13 发布与成功判定
- 点 `button[id=publishBtn]` 发布。
- **成功判定（双条件）**：页面出现「已提交发布」弹层 **且** 视频管理列表（`pages.publish?activeTab=management`）出现该新记录（含平台时间+商品+视频ID）。
- 网络错误/无反馈/长时间加载等无法确认 → 不算成功。普通技术错误最多重试 3 次（每次重试前重查页面状态）；3 次仍失败 → 状态=发布失败，记录原因+重试次数，继续其他任务。

### 3.14 任务表回填（发布成功后）
- 在任务表用名称框跳转 E 列对应格（如 E415）→ F2 → 在 `alloy-simple-text-editor` 输入平台发布时间（格式 `2026/9/28 13:21`）→ 回车。
- **必须用 JS API 回读验证保存**：
  ```js
  window.SpreadsheetApp.workbook.worksheetManager.getSheetList()[0].getCellDataAtPosition(r, 4)
  ```
  读到刚填的时间才算回填成功（直接 `setCellDataAtPosition` 不持久化，勿用）。
- 回填时间 = **发布成功后的平台显示时间**，不是点击发布的时刻。

### 3.15 每店总结
- 本店全部任务处理完（或暂停/延期/失败）→ 写一段总结：做了什么、遇到什么问题、怎么解决、剩余任务状态。
- 追加到当日运行记录 md（`paths.run_log_dir` 下 `YYYY-MM-DD运行记录.md`），文件不存在则新建。

## 4. 运行报告（全部店铺结束后）

输出：总任务数 / 已完成 / 发布失败（含原因+重试次数）/ 跳过 / 人工处理中（含原因+用户需做什么）/ 待处理 / 延期（注明「下一次运行继续处理」），**按店铺分别统计**。

## 5. 人工处理协议

- 触发时机：见 3.2/3.3/3.4/3.6/3.8/3.13 的「暂停」点；页面结构明显变化；未知关键弹窗；需要业务选择。
- 提示格式（缺一不可）：**当前什么问题 / 当前在哪个页面 / 用户需要做什么 / 完成后点什么按钮**。
- 只暂停该店，其他店继续；用户完成后点「我已完成」→ 重新检查页面/数据后继续本店。

## 6. 断点续跑

- Agent 重启后：重新全表扫描（3.1 防重复检查）→ 已发布跳过 / 待处理继续 / 已下载从上传继续 / 发布中重查页面（禁止直接再点发布）。

## 7. 浏览器操作红线（对 Agent）

- 每次打开新页默认等 ≥5 秒，目标元素存在且可操作、无弹窗阻挡才点击；禁止页面刚开就点。
- 所有点击：定位 → 确认存在 → 确认可操作 → 确认页面状态 → 点击 → 等页面变化 → 验证结果。元素不存在不得点附近位置。
- 用 ref-first（`bu.snapshot` 的 document-scoped ref），ref 失效（导航/重渲染/BU_REF_STALE）→ 重新观察取新 ref；上传用 `bu.upload_file(selector,...)`。
- 页面状态与 SOP 不一致 → 暂停人工处理，不自行猜测。
- 登录/验证码/需要用户接管 → `interaction.request_action` type=browserControl，绝不绕过。

## 8. 同步协议（可选，GitHub）

- 运行记录与技能更新推送到 `sync.repo`：部署机本地执行 `sync_skill.ps1`（**本地私有工具，不随仓库发布**；gh API 直传，带重试；不依赖 git 443）。
- 同步前确认 `gh auth status` 已登录；失败重试 3 次后仍失败 → 记录原因，不阻塞发布主流程。
