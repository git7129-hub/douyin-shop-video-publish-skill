# 抖店短视频自动发布（Agent Skill · 可配置版）

## 零、安装与配置（部署者必读）

### 0.1 环境依赖

| 依赖 | 说明 |
|---|---|
| 支持 Agent Skills 的客户端 | 将本技能目录（含 SKILL.md）放入客户端 skills 根目录即可被识别 |
| 浏览器自动化 | 豆包浏览器 / `computer_use_tool`（plane=bu，`seed_browser_use`） |
| Python 3 + openpyxl | 读取本地违禁词表 / 商品ID.xlsx（可选，页面可替代部分功能） |

### 0.2 安装步骤

1. **获取技能**：将本仓库 `skills/douyin-shop-video-publish/` 整个目录复制到客户端的 skills 根目录；
2. **新部署者请先读 `CONFIG-GUIDE.md`**（同目录），按其中「第一步→第七步」手把手完成安装与配置（约 15 分钟）；
3. **执行 Agent 请以 `AGENT-GUIDE.md` 为操作协议**（同目录）：含每步输入/输出、工具调用、JS 片段、判定与暂停条件、回填与断点续跑——本文件只给业务方法论；
4. **创建配置**：复制 `config.example.json` 为 `config.json`（与 SKILL.md 同目录），按「一、配置项说明」填写；
5. **准备资产**：按配置路径放置违禁词表（xlsx）与商品ID表（xlsx 或腾讯文档）；
6. **登录**：按 0.3 完成抖店 / 任务表平台登录；
7. **验证**：运行一次「全表扫描」（见「二、1」）确认能读到任务表，即部署成功。

### 0.3 登录流程（调用时引导，不保留登录状态）

> 技能**内置**任务表 / 商品ID表 / 违禁词表地址（见 config.example.json），但**不保存任何登录状态**（无 cookie、无 token、无自动登录）。每次调用时由 Agent 现场引导登录：

1. **抖店**：打开 `pages.home` → 未登录则引导企业微信扫码登录 → 确认右上角可见店铺名与「切换组织/店铺」；
2. **任务表/商品ID表（腾讯文档）**：打开内置链接 → 未登录则引导用户登录（扫码/账号）→ 确认能读取数据（`window.SpreadsheetApp...` JS API）；
3. 登录完成后仅本次会话有效，**不写入任何文件、不持久化**；下次调用需重新登录（Agent 会再次引导）。

### 0.4 安全与分享

- **技能内置真实业务链接**（任务表/商品ID表/违禁词表地址），这些是资源地址而非凭据；打开后需登录才能看内容；
- **不保留登录状态**：任何调用都不保存 cookie/token/密码，登录仅当次会话有效；
- 分享给他人时，对方打开内置链接仍需其自己账号的文档权限；请自行评估分享范围，必要时可将链接替换为对方自己的文档；
- 分享时只分享本技能目录（SKILL.md + config.example.json + 引导文档），不包含登录凭证与运行历史。

## 一、配置项说明（config.json）

所有私有信息一律放 `config.json`（模板见 `config.example.json`），字段：

| `paths.video_dir` | 视频暂存目录 | `D:\douyin_shop_video_publish\temp file\` |
| `paths.banned_words_xlsx` | 违禁词表（本地 xlsx，也支持在线链接） | `D:\douyin_shop_video_publish\违禁词表.xlsx`（内置） |
| `paths.product_id_xlsx` | 商品ID本地表（可选） | `D:\douyin_shop_video_publish\商品ID.xlsx` |
| `paths.run_log_dir` | 运行记录目录 | 私有 |

## 二、核心执行流程

### 1. 启动：全表扫描（防遗漏纪律）

- 用 JS API 读取任务表（禁用硬编码行区间）：
  ```js
  window.SpreadsheetApp.workbook.worksheetManager.getSheetList()[0].getCellDataAtPosition(r, c)
  ```
- 列映射（默认，可在 config 扩展）：c0=A 视频名（超链接在 `cell.value.r[].hyperlink.url`）、c3=D 店铺、c4=E 发布时间、c5=F 备注；E 行号 = 数据行号 + 1。
- 遍历 0→真实末行，按店铺列分组，建立每店完整任务清单（行号+视频名+发布时间+备注）。
- 识别：已完成（E 有值跳过）、待处理（E 空且非跳过）、测试行（备注含「测试」跳过）、违规视频（备注含违规跳过）。
- 每店处理前后都重新全表扫描一次，确认无新增、回填生效。

### 2. 店铺队列与并发（店铺清单跟随用户，不写死）

- **店铺清单来源（动态发现，优先）**：任务表 D 列去重得到「任务店铺集合」，并读取抖店登录账号实际可访问店铺（首页 → 右上角店铺名 → 「切换组织/店铺」弹窗 → 枚举全部可选店铺）得到「账号店铺集合」。
  - 任务店铺 ∈ 账号店铺 → 纳入队列，正常处理；
  - 任务店铺 ∉ 账号店铺 → **该店暂停人工处理**（提示：该店铺不在当前登录账号下，请切换到对应账号或更换账号，完成后点「我已完成」），不猜测、不跳过。
- **新增店铺询问（当前仅单个店铺时）**：若任务表存在未发布任务的店铺 X，而当前处理店铺集合**只有 1 个店铺 Y（X≠Y）** → **暂停并询问用户**：「任务表中有店铺 X 的视频未发布，当前仅处理店铺 Y，是否将 X 新增为处理店铺？」
  - 用户答「是」→ 将 X 纳入本次处理清单，继续执行；
  - 用户答「否」/「不用」→ **停止处理该店 X**（本次不发布 X 的任何视频），并把用户习惯记录到当日运行记录（如「用户选择暂不处理店铺 X」）；**后续运行遇到 X 默认沿用该习惯不再询问**，直到用户明确说「新增店铺 X」才解除并处理。
- `config.json` 的 `shops` 为**可选白名单**：留空（默认）= 完全跟随登录用户自动发现；填写 = 仅处理白名单内店铺（对任务表 D 列过滤）。
- 并发单位 = 店铺，默认并发 `rules.max_concurrency`（可配置 1-5）。
- 同店严格按任务表顺序串行；不同店可并行。
- 每店独立维护：登录态、任务、发布数量、发布时间、异常状态。

### 3. 店铺切换（已验证路径）

- 必须在**首页**操作（短视频运营页无入口）。
- 点击右上角店铺名区域（含头像+店名+箭头，约坐标 940,30）→ 弹出店铺信息侧栏 → 点击「切换组织/店铺」→ 弹出「请选择店铺」列表（可见约 4 家，下方需滚动）→ 点击目标店铺。
- 切换后验证页面右上角店铺名 = 目标店铺。
- 若子账号无首页权限：短视频运营页权限正常，直接导航即可，不影响发布。

### 4. 挂车额度确认

- 进入短视频运营页，读取「今日挂车短视频可发 N/M 条」。
- 额度以页面实际显示为准，不询问用户、不自设上限。
- **规则**：当天有挂车额度就用挂车模式发完；发完当天挂车额度后**不再发布非挂车视频**（剩余任务延期，下一次运行继续）。

### 5. 视频下载

- 从任务表 A 列超链接取微盘地址，打开 → 点「下载」按钮 → `bu.wait_for_download` 拿到完整文件（禁止把 `.crdownload` 当完成）。
- 下载前检查本地是否已存在同任务文件（存在且完整则复用）。
- 命名：`店铺名_日期_原名`；AI 作品文件名含 `_AI`，**不得自行猜测 AI 属性**。
- 移入 `paths.video_dir`。

### 6. 上传（挂车面板）

- 短视频运营 → 「单独发视频」→ 挂车模式。
- `bu.upload_file("input[type=file]", 本地绝对路径)`；等待上传 100%、出现封面推荐即完成。
- 页面重渲染会失效 refs / input[type=file]，需重走面板；`upload_file` 用 selector。

### 7. 商品匹配（禁止猜测）

- 商品ID本地表 / 在线表（含型号→编号→话题）→ 发布面板「选择商品」。
- 商品查询：按「商品名称」label 定位父容器 input（原生 setter + input/change 事件）→ 点真 `button[type=submit]`「查询」。
- **唯一匹配** → 自动勾选 radio → 确认「已选商品（1/1）」→ 确定。
- **多匹配** → 暂停人工处理，列出匹配项请用户选择；**无匹配** → 人工处理（用户指定编号或按异常流程）；禁止随机选择。
- 多店铺数据隔离：不同店铺同型号商品编号可能不同，以本店实际查询结果为准。

### 8. 标题与作品描述

- 优先使用平台 AI 自动生成（小黄车标题 + 作品描述），必须等待生成完成；未生成才自行生成，不得留空。
- 生成慢不算失败，继续等待。

### 9. 违禁词检查与换一换

- 对照 `paths.banned_words_xlsx`（典型违禁：超、最、第一、顶级、必备、神器、微信、特有、极速、秒杀等；「顺手」「太方便」不违禁——以实际表为准）。
- 有违禁 → 点描述区「已为你生成作品描述」内的「换一换」（div/span 文本元素，非 button）。
- **最多自动换一换 `rules.huan_yihuan_max` 次（默认 5）**；达到上限后仍含违禁 → **停止自动换一换**，按新规则：
  1. 打开商品ID在线表，**全表扫描**（探测真实维度，如 `_Md`），查该型号话题栏；
  2. 找到对应话题 → 用其替换描述话题（按 SOP 方式添加）；
  3. 找不到 → 进入人工处理，请用户提供合规话题或处理方式。
- 禁止超过配置上限的换一换次数。

### 10. AI 内容声明

- 文件名含 `_AI` → 点「无需添加自主声明」→ 选「内容由 AI 生成」。
- 不含 `_AI` → 跳过。

### 11. 话题添加（SOP，强制）

- **必须**：输入「#话题名」→ **等待下拉选项出现** → **选择第一个匹配选项** → 话题成为可识别标签（DOM 中为 `topicItem` 元素）才计入成功。
- 禁止把 `#+话题` 当纯文本一次性输入（不生效）。
- 非挂车流程：每条视频随机 3-5 个话题，至少成功 3 个；挂车流程 AI 生成的描述话题为有效标签（topicItem），核验后无需手动添加。
- 话题来源优先：商品ID表话题栏 → 用户提供 → 商品相关合规词。

### 12. 发布时间（平台时间优先）

- 时间基准：Windows 本机当前时间；每店独立计算。
- 当天该店第 1 条 → **立即发布**；第 2 条及后续 → 上一条该店平台发布时间 + `rules.timed_hours_gap` 小时 → **定时发布**。
- 抖店定时限制：仅支持未来 2 小时-14 天；输入计算时间后**以平台实际显示/调整时间为准**（早于最早可定时 → 平台自动调整为最早可用）。
- 下一条计算时间超过当天允许窗口（`rules.publish_window`）→ 停止该店当天剩余任务（延期），不强行发布、不自改时间。
- 回填时间 = **发布成功后的平台显示时间**（不是点击发布的时刻）。

### 13. 发布前最终检查（缺一不点）

店铺正确 / 任务仍是目标任务 / 任务表未被其他进程完成 / 视频正确且已上传完 / 商品正确 / 标题与描述存在 / 违禁词已处理 / AI 声明正确 / 话题满足要求 / 发布时间正确 / 页面仍是发布页 / 无阻挡弹窗。任何一项无法确认 → 不点击发布。

### 14. 发布与成功判定

- 点击发布（`button[id=publishBtn]`）后**不能直接判定成功**。
- 成功判定：页面出现「已提交发布」弹层 **且** 视频管理列表出现新记录（含审核中/审核通过/定时发布中 + 平台发布时间 + 商品 + 视频ID）。
- 网络错误/无反馈/长时间加载等无法确认 → 异常处理，不得写成功。
- 普通技术错误最多重试 3 次（每次重试前重新检查页面状态）；3 次仍失败 → 状态=发布失败并记录原因和重试次数，继续其他任务。

### 15. 任务表回填

- 只有发布成功后才回填：名称框跳转 E 列（如 E415）→ F2 → `alloy-simple-text-editor` 输入 `2026/9/28 13:21` 格式 → 回车 → **JS API 回读验证保存**。
- 注意：直接调 `setCellDataAtPosition` 不持久化，必须走 UI 编辑路径。
- 回填后及时保存；不得等全部任务完成后才回填。

### 16. 每店总结记录 + 运行报告

- 每处理完一个店铺：先总结并记录遇到的问题与解决方法（追加到当日运行记录 md）。
- 运行结束生成报告：总任务数 / 已完成 / 发布失败 / 跳过 / 人工处理中 / 待处理，按店铺分别统计；延期任务明确记录「已延期，下一次运行继续处理」。

| 3 | 商品无编号/多匹配 | 暂停人工处理，用户指定；禁止猜测 |
| 4 | AI 描述含违禁词（超/必备/神器/微信） | 换一换最多 5 次；仍违禁 → 查商品ID在线表话题栏（全表扫描）→ 找不到 → 人工 |
| 5 | 描述话题手动输入 #+话题 不生效 | **话题必须按 SOP：输入 #话题 → 等待下拉 → 选第一个匹配 → 成为 topicItem 标签** |
| 6 | 定时时间早于平台最早可定时 | 平台自动调整为最早可用，以平台显示为准回填 |
| 7 | 商品ID表扫描不全 | 探测 sheet 真实维度（`_Md`），全表扫描 |
| 8 | 换一换按钮非 button 标签 | 用文本定位描述区 div/span「换一换」 |
| 9 | 子账号无首页权限 | 短视频运营页权限正常，直接导航即可 |
| 10 | 多 tab 切换误判「面板已关闭」 | 切回目标 tab 后发布面板/上传状态保留，避免重复上传 |

## 五、默认业务规则（可在 config.rules 覆盖）

1. 登录页/短视频运营页自动确认挂车额度，不每次询问用户；
2. 测试视频无需发布（任务表备注含「测试」）；
3. 有违规提示的视频不发布；
4. **当天有挂车额度就用挂车模式发完，发完当天不再发布非挂车视频**；
5. **定时发布时间以平台实际接受/显示时间为准；回填时间 = 发布成功后的平台时间**；
6. **换一换达上限仍违禁 → 先查商品ID表话题栏（全表扫描）→ 找不到对应话题再进入人工处理**；
7. 每处理完一个店铺先总结并记录遇到的问题和解决方法；
8. **启动时自动读取最近一次正确运行的记录**（`paths.run_log_dir` 下最新 `YYYY-MM-DD运行记录.md`），优先复用其中已验证的正确步骤与问题解决方法，而不是每次重新计算；
9. **新增店铺询问**：任务表存在未发布任务的店铺 X，而当前仅处理 1 个店铺 Y（X≠Y）时 → 暂停询问是否将 X 新增为处理店铺；用户拒绝则停止处理该店 X 并把习惯写入运行记录，后续运行沿用该习惯不再询问，直到用户明确表示新增店铺 X。

## 六、红线（禁止事项）

禁止重复发布已完成视频；禁止未确认店铺/商品/上传完成就发布；禁止未确认发布成功就写完成；禁止猜测商品编号/页面按钮/挂车或非挂车；禁止超过配置上限的换一换；禁止一个店铺失败停止全部店铺；禁止同店并发多任务；禁止页面未加载完成就点击；禁止修改用户原始任务数据；禁止虚假修改状态；禁止把真实 config.json 提交到公开仓库。

## 七、断点续跑

- 重启后重新全表扫描：已发布（E 有值）跳过；待处理继续；已下载（本地文件存在）从上传/发布继续；发布中 → 重新检查页面状态，不得直接再点发布。
- 任务表写回及时，即使 Agent 中途关闭，已完成任务状态保留。

## 八、更新维护约定

- 版本号在每次更新时递增（2.0.0 → 2.0.1 → ...）。
- 分享时仅分享本目录（SKILL.md + config.example.json + assets），不包含真实 config.json 与运行历史。
