## 二、逐项详解：现象 → 原因 → 解决 → 防再犯

### 问题 1：回填操作误清空整张任务表（最严重事故）
- **现象**：任务表所有单元格被清空（JS API 回读全表为空），当时正在清除 data422 的误写。
- **根因**：清除误写时焦点不在编辑框内，Ctrl+A + Backspace 在表格层触发**全表选中后删除**，而非单元格清除；腾讯文档无跨会话 Ctrl+Z 撤销。
- **解决**：用户通过腾讯文档**历史版本功能手动还原**；我随后建立了 	ask_sheet_backup_20260929.txt 全表备份（A/D/E/F 0→430 行），用于核对还原完整性。
- **防再犯**（已写入 SKILL）：
  - 清除单元格**禁用 Ctrl+A+Backspace**，必须走：名称框跳转 → 聚焦 #alloy-simple-text-editor → Range.selectNodeContents 只选编辑框内容 → execCommand('insertText','') 置空 → Enter 提交；
  - 每次回填前先 JS API 全表备份/记录关键行现值；回填后必回读验证 ±1 行；
  - 关键操作前确认 ctiveElement 确实在编辑框内。

### 问题 2：回填误写（时间写入错行，data421 被 12:38:35 覆盖）
- **现象**：给 data422 回填 12:38:35，回读发现 data421（09:10:10 正确值）被覆盖。
- **根因**：**名称框 Excel 行号 = 数据行号 + 1**（表头占 1 行）。名称框跳转 E422 实际定位的是**数据行 421**（data421），而非 data422；按数据行号直接跳转必然写到上一行。
- **解决**（实测验证的有效路径）：
  1. 名称框跳转 E{数据行+1}：如修复 data421 用 E422，写 data422 用 E423；
  2. 跳转后**必须验证编辑框打开显示的是目标单元格当前值**（防止跳转假成功）；
  3. 全选替换 → JS Enter 提交 → JS API 回读验证三行（data420/data421/data422）。
- **防再犯**（已写入 SKILL 问题16）：跳转目标一律用 E{数据行+1}；修改前先验证编辑框内容；提交后回读 ±1 行确认无扩散。

### 问题 3：店铺切换入口不可见（窄视口 639px）
- **现象**：内嵌浏览器视口 639×827，抖店首页文档宽 1264，右上角店铺名/切换入口在视口右侧外；页面 overflowX=visible 无横向滚动条。
- **失败尝试**（勿重试）：u.click ref（元素视口外）、JS el.click/dispatchEvent（React 合成事件不触发）、u.click_xy 坐标（误入服务市场页面）、window.scrollTo/scrollIntoView/.scrollLeft（无滚动力）、桌面控制放大窗口（PIP 初始化失败）、u.cdp 调整视口（CDP session not found）。
- **解决**：JS 设置 document.documentElement.style.zoom='0.5' 缩放页面 → 店铺名进入视口（rect x≈898）→ u.click_xy(915,20) → 出现「切换组织/店铺」→ JS 点击 → 弹窗列出账号全部店铺（艾印/采寻/码捷/爱客/非繁/码客/码上/蓝讯/启锐）→ 选中目标店铺 → 验证右上角店铺名。
- **防再犯**：导航新页面后 zoom 丢失需重设；页面切换加载期间 u.js 可能返回 webpack bundle 源码，须 wait_for_load 后重试（已写入 SKILL 问题15）。

### 问题 4：微盘下载按钮隐藏
- **现象**：微盘分享页下载按钮因窄视口响应式 header display:none 隐藏，CSS zoom 也无效。
- **解决**：打开视频链接触发请求后，用 u.network_requests() 抓取 **downloadobject 直链**（szfront.wxwork.qq.com/downloadobject?fileid=...&filename=...，filename 参数含视频原名）→ u.download(直链) 完整下载（禁止把 .crdownload 当完成）。
- **防再犯**：直链 URL 含 base64 fileid 票据，**不可硬抄**，每次导航后重新抓取。

### 问题 5：商品编号查询误填
- **现象**：第一次把编号 3615901691003676804 误填入「**商品名称**」框 → 查询无结果；用户后台核对编号存在。
- **解决**：发布面板商品弹窗有「商品名称」「商品编号」两个输入框 → **编号必须输入「商品编号」框**（label「商品编号」旁的 input，native setter + input/change）→ 点真 utton[type=submit]「查询」→ 唯一匹配「采寻出库仪菜鸟兔喜多多奚鸟邮政妈妈驿站出库仪一体机多系统扫描」（¥2,399，库存 12285）→ 勾选 radio →「已选商品（1/1）」→ 确定。
- **防再犯**：按 label 定位输入框后再输入；查询无结果先核对是否填错框/填对编号，不猜不跳过。

### 问题 6：「添加小黄车商品」弹窗不响应
- **现象**：点「添加小黄车商品」后弹窗不出现（JS 合成事件/ref 点击/坐标点击均无效）。
- **解决**：改用发布面板真实 utton「**选择商品**」成功打开商品弹窗。
- **防再犯**（已写入 SKILL）：商品弹窗入口用「选择商品」button，不用「添加小黄车商品」div。

### 问题 7：WebView 键盘输入被阻塞
- **现象**：u.press_key（F2/Esc/Enter）、u.type 在本 WebView 反复抛 could not acquire input focus; blocked Input command。
- **解决**：键盘类操作**全部改用 JS 事件链**：
  - 名称框跳转：JS 聚焦 input → native setter 设值 → 派发 input/change + keydown/keypress/keyup Enter（bubbles）→ 跳转生效并自动打开编辑框；
  - 编辑框输入：JS ocus() + Range.selectNodeContents 全选 + execCommand('insertText', ...) 替换；
  - 提交：JS 对编辑框派发 keydown/keypress/keyup Enter。
- **防再犯**：WebView 环境下禁用手动键盘命令，统一走 JS 事件链；u.click（鼠标事件）不受影响可继续用。
